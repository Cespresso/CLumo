# ヘッドホンスタンド版 CLumo

既存の standalone / companion に続く第3のファームウェア。XIAO ESP32-C3 のヘッドホンスタンド専用で、Android は `companion/android/` の共通アプリを使用する。
初期コードは maker-projects の `nothing-headphone-accessory/firmware/`（2026-11-14、配線記録コミット d0a51c6）から移植。本番ソフトウェアの編集元は今後このディレクトリ。

ESP32側の構成・書き込み手順・接続トラブルの知見は[ファームウェアREADME](firmware/README.md)を参照。

[完成写真・配線図・P1S用3MF](../hardware/headphone-stand/README.ja.md)もこのリポジトリに収録しています。

[写真付きアセンブリガイド（日英）](../hardware/headphone-stand/assembly/)では、操作部の接続と筐体の組み立て順序を説明しています。

## 操作と接続

- 初期割り当て：左／右ボタンは前へ／次へ。ノブ回転は音量、1回押しは再生／一時停止、2回は次へ、3回は前へ。最後に離して300msで連打を確定する。AndroidとWebから変更・初期値復元が可能。
- ノブ3秒長押し：新しいスマホのペアリングを60秒受け付ける。Bluetoothマークが点滅し、短押し操作は送らない。
- 受付中は現在の接続を切り、登録済み／未登録の双方を受け付ける。接続先を切り替える場合は切り替え元のBluetoothを切断する。成功または60秒後に通常へ戻る。長押し自体では登録情報を消さない。
- 通常時は登録済みスマホのみ接続可能。再起動後も登録情報・表示設定をNVSに保持する。
- AndroidのBluetooth設定から `CLumo-Stand-XXXX` とペアリングし、CLumoアプリで追加する。スタンドはパスキー入力不要（既存CLumoの123456とは別）。
- BLE HID Consumer Controlにより、アプリ終了後もメディア操作できる。Androidの音量LEDとビジュアライザにはアプリの配信が必要。iPhoneの音量LEDはAMSで取得するためアプリ不要。
- 音量LEDは下から1～3灯。音量0・不明・切断時は消灯。Androidの状態報告が2秒途絶えると不明になる。実音量取得中は音量表示を維持し、不明な場合だけ操作中に180msのシーケンスを表示する。
- 表示優先順位：ペアリング受付 → 操作表示（500ms）→ ビジュアライザ（更新から2秒）→ 待機表示（固定／横スクロール／消灯）。

長押し3秒・受付60秒は今回の初期値。複数スマホとの同時接続は行わない（最大1接続）。登録はNimBLE標準設定の最大3台。4台目を登録すると最も古い登録が置き換わる。通常時に複数の登録済みスマホが近くにある場合は接続先をAndroid側で選ぶ。

## 確定配線

| 用途 | XIAO / GPIO | 色 |
| --- | --- | --- |
| MAX7219 DIN | D0 / 2 | 青 |
| MAX7219 CLK | D8 / 8 | 黄 |
| MAX7219 CS | D9 / 9 | 緑 |
| LED 上／中／下 | D10 / 10、D7 / 20、D6 / 21 | 黄／緑／青 |
| 前曲／次曲 | D1 / 3、D2 / 4 | 黄／緑 |
| ノブ押込み | D3 / 5 | 青 |
| エンコーダー A／B | D4 / 6、D5 / 7 | 黄／緑 |

MAX7219の電源はUSB 5V（赤）、GNDは黒。レベル変換なしの実機構成。SPI MODE0、2MHz。LEDはGPIO→各抵抗→アノード、カソード→個別GNDのHigh点灯。電源LEDは3V3（白）→抵抗→LED→GND。ボタンとエンコーダーは内部プルアップ、共通端子GND。
掲載用の[採用配線図と印刷案内](../hardware/headphone-stand/README.ja.md)を参照してください。制作元はmaker-projectsの`nothing-headphone-accessory`で、出典・ハッシュは同ページから確認できます。

## 音量操作の表示

比較サンプルの「03 ＋／−のパルス」を採用。音量アップは＋が小→中→大に膨らみ、ダウンは−が大→中→小に縮む（各3段階、1周期500ms）。連続して同じ方向へ回す間はパルスを継続し、最後の操作から500ms後にビジュアライザまたは待機表示へ戻る。方向を変えると、アップは小、ダウンは大から開始する。音量の値ではなく操作方向を表し、実音量は3灯のLEDが示す。

比較用HTMLは `review/volume-animation-samples.html`。採用の元は03、通常速度。サンプルは比較時のまま保存しており、本番ではその後の指定によりマイナスのみ縮小に変更した。前／次曲の矢印表示とは別の表現にする。

## マトリクスの取り付け方向

正面から見て、従来CLumoに対してマトリクスを反時計回りに90°回して取り付ける（2026-11-14実機確認後の指定）。ファームウェアのSPI出力直前で画素を時計回りに90°回転し、見える向きを補正する。
待機表示・ビジュアライザ・操作表示・ペアリングマークのすべてに適用。アプリの描画と保存済みフレームは従来の論理座標（上から行、最上位ビットが左）を維持するため、Android側や保存データの変換は不要。

## BLEプロトコル v4

サービス `d9730000-b19e-4c81-a5e8-36fbd47a9c10`。下表は先頭UUID末尾4桁。INFO以外は暗号化接続が必要。

| UUID | 内容 | 転送 |
| --- | --- | --- |
| 0001 | INFO `[4,1]`：プロトコル4、機種1 | 読取 |
| 0002 | 永続UUID 16バイト | 読取 |
| 0003 | 輝度0～15 | 読取・書込・通知、保存 |
| 0004 | 8×8行データ8バイト | 読取・書込・通知、保存 |
| 0005 | ビジュアライザ列高8バイト、各0～8 | 応答なし書込 |
| 0006 | 待機0固定／1スクロール／2消灯 | 読取・書込・通知、保存 |
| 0007 | 音量状態 `[0]` 不明／`[1, percent]` 確定値0～100 | 応答なし書込、アプリから500ms周期 |
| 0008 | 表示設定全体78バイト（輝度・モード・最大8コマ・周期） | 読取・書込、保存 |
| 0009 | 操作割り当て7バイト | 読取・書込、保存 |

既存CLumoのタイマー／ポモドーロコマンドは使わない。AndroidはサービスとINFOの両方で識別する。v1/v2/v3との互換はないため、スタンドとAndroidアプリを両方更新する。

## ビルドと検査

`headphone-stand/firmware/` から：

```sh
rustup run 1.97 cargo test --locked
rustup run stable cargo fmt --check
rustup run nightly-2025-11-01 cargo build --locked --release --features device --bin headphone-stand --target riscv32imc-esp-espidf -Z build-std=std,panic_abort
espflash save-image --chip esp32c3 --flash-size 4mb target/riscv32imc-esp-espidf/release/headphone-stand target/headphone-stand.bin
```

取得済みESP-IDFを使う場合は `IDF_PATH` にそのv5.2.2ディレクトリを指定する。今回の実機ビルドはmaker-projects内の取得済みv5.2.2を参照した（ソースコードは共有しない）。

ESP-IDF v5.2.2、Rust nightly-2025-11-01、4MBフラッシュ。既存実機の0x10000アプリ領域へ書込み、ブートローダー・パーティション表・NVSを保持する。既存基板のブートローダーは4MB対応済み。別基板に初回書込みする際は4MBに合うブートローダー・パーティション表も必要。

Androidは `companion/android/` で `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest ktlintCheck lintDebug`。SDKは `ANDROID_HOME` またはlocal.propertiesで指定する。
通常の実機回帰はペアリング済みスタンドを指定し、`HeadphoneStandHardwareTest#volumeV2AndReconnect` を実行する。表示設定を書き換える旧テストは複数コマアニメーションを完全に復元できないため、詳細はファームウェアREADMEを参照する。物理的な点灯・回転方向は目視確認が必要。

## Wi-Fi設定モードの切り替え試作

以下は段階ごとの実装・検証記録。初期試作の制限や確認待ちは当時の状態で、現在の編集機能と表示動作は後段の各節を参照。

- 前曲＋次曲を同時に3秒長押しすると、進捗表示の後に再起動してWi-Fi設定モードへ移る。途中で離すとキャンセル。両方を一度離すまで再度発動しない。
- Wi-Fi設定モードではBluetoothを初期化せず、音量LEDを消灯し、マトリクスにWi-Fiマークを表示する。
- スマホで `CLumo-Setup-XXXX` に接続し、`http://192.168.71.1/` を開く。今回の試作はパスワードなし・最大1端末・読み取り専用の接続確認ページ。マトリクス編集は未実装。
- 通常モードへ戻る操作も前曲＋次曲の3秒長押し。自動復帰タイマーやブラウザの「保存して終了」は設けない。
- モード切り替え時に短い再起動が入る。登録済みスマホとのペアリングと表示設定は保持。電源再投入では通常モードで起動する。
- 通常の前曲・次曲は同時押し判定のため、チャタリング除去後150ms待って送信する。2つ目を押すのが遅い場合、先の曲操作は既に送信されることがある。
- ノブの3秒長押しによる新規ペアリングは通常モードで従来どおり。Wi-Fi設定モードではノブと単独の曲ボタン操作は無効。
- ホストテスト24件成功。短押し、連打、同時押し、キャンセル、長押し連続発火抑止、起動時押しっぱなし抑止を検証。

## ブラウザの待機アニメーション編集

設定用Wi-Fiのポータルにプリセット選択と8×8ドット編集を追加。プリセットは音符・鼓動・波・CLumoロゴ。1〜8コマを追加・複製・削除・前後へ移動でき、ドットはタップまたはなぞって変更する。1コマ100〜2000msと明るさ0〜15を調整可能。表示方法はコマ再生（1枚なら静止画）・先頭コマ横スクロール・消灯。

プレビューはブラウザ内だけで再生し、設定モードの本体はWi-Fiマークを維持する。「本体に保存」で表示と明るさを一括保存し、設定モードは継続する。両ボタン3秒長押しで通常モードへ戻ると、保存済み設定を読み込む。未保存の編集は本体に反映しない。通常モードでは操作アニメーション・音声ビジュアライザを優先し、それらが終わると保存した待機表示を再生する。

保存形式は既存の10バイトを読み取り可能とした78バイト拡張（旧10バイト＋バージョン1＋コマ数＋LE16周期＋8コマ×8行）。旧Android GATTの形式は維持。明るさ変更はコマ再生を保持し、絵または待機モードの変更はコマ再生を解除してAndroidの指定を優先する。Androidからは先頭コマを代表の絵として読み取れる。

設定モード専用API: GET `/api/settings`、POST `/api/save`。POSTはContent-Type `application/octet-stream`・78バイト固定。値不正は400、保存失敗は500で保存済み状態を保持する。ブラウザUIは送信中の編集を停止し、8秒で応答確認を打ち切って再試行を案内する。

ホストテスト32件成功（旧設定、新形式境界、再生ループ、Android上書き、既存機能）。fmt・ビルド・差分チェック成功。ローカル模擬APIで8コマプリセット・ドット編集・保存後再読み込みをブラウザ確認。実機画像サイズ1,342,144バイト。

実機へ1,342,144バイトを書き込み、ハッシュ一致。Androidを経由したHTTP検証で、編集HTMLがソースと一致、GET設定78バイト、プレビュー後の保存値不変、9コマ・不正長の400拒否、8コマの保存／読み戻し一致を確認した。検証後は元の設定を保存し直して復元。物理マトリクスの見え方、再起動後の保持、Androidアプリから上書きする実機操作は未確認（保存形式・再生・上書き規則はホストテスト済み）。

CLumoロゴのプリセットは通常CLumoの接続待ち画面 `companion/firmware/src/assets.rs` の `ICON_DISCONNECTED` を使用し、完成形の8行を完全一致させたもの。下から線を描いて完成形を保持し、逆に縮む8コマ（200ms/コマ、周期1.6秒）で、旧「きらめき」を置き換えた。保存済みのユーザー作品は変更しない。

「本体に保存」は保存だけを行い、設定モード中の表示・明るさを変更しない。設定モード中はWi-Fiマーク（両ボタン長押し中のみ進捗）を維持し、通常モードへの復帰時に最新の保存内容を適用する。

## 音量操作時の3灯シーケンス

実音量を取得できている間は、ノブ回転中も実音量の点灯数を表示し、3灯シーケンスを出さない（音量0も取得済みとして消灯を維持）。音量が不明なときだけ、ノブ回転時に1灯ずつ表示する。音量アップは下→中→上、ダウンは上→中→下、各60ms。単発は180ms、同方向の回転が180ms未満の間隔で続く間は先頭に戻さず流し続ける。逆方向または180ms以上の間隔では先頭から再生。音量を取得した時点で直ちに実音量表示へ切り替える。音量不明のままなら最後の回転から180ms後に消灯する。マトリクスの500msパルスとは独立したタイミング。

## 音量取得と接続の共通基盤（v2）

`firmware/src/volume.rs` は接続世代・取得元・取得状態・型付きの音量値を管理する。Androidの2秒の生存判定はAndroidVolumeが担当し、表示側Stateは有効な音量値だけを受け取る。AMSも同じ状態更新口を使用する（実装・検証は後述）。

`firmware/src/connection.rs` は暗号化・HID購読・サスペンドを一つの接続スナップショットにまとめ、音量とビジュアライザを各1件の最新値メールボックスに保持する。BLEコールバックは表示状態を変更しない。メイン処理が世代変更時にHID送信待ちと揮発表示を破棄してから現在のイベントを反映する。保存設定は残す。暗号化を失った場合も新しい世代へ進めて保留値を破棄する。

AndroidのMediaVolumeSourceは取得専用で、500msごとにnullableな音量を発行する。送信はDeviceSession/DeviceTransport側で行う。状態報告の到着は生存確認、内容は音量の観測結果として別々に解釈するが、通信上は一つのスナップショットにまとめる。パケット欠落後も次の報告で復帰でき、音量が変わらないこととアプリ停止を区別する。

共通基盤v2は実機へ展開済み（下記参照）。iPhoneとのAMS接続も追加済み（後述）。

検証: Rust 42件、Android 292件のテスト成功。Rust fmt、ESP32-C3 releaseビルド、Android assembleDebug／compileDebugAndroidTestKotlin／ktlintCheck成功。生成したファームウェアは1,343,056バイト。Android lintDebugは未変更の依存バージョン更新通知5件（Gradle、AGP、Compose BOM、Core KTX、DataStore）がwarningsAsErrorsでエラーになり終了。今回のコードに対するLint指摘はなし。依存更新は本変更に含めない。

## AMS音量取得

iPhoneの既存の暗号化BLE接続上でAMSを探索し、Service Changedのindicate、Entity Updateのnotify、Player Volume `[0,2]` を順に購読する。メディア操作はHIDのまま、AMS Remote Commandは使用しない。`ams.rs`が音量のUTF-8数値（0..1）を検証し、`ams_transport.rs`がNimBLEのC APIとの境界を担当する。

AMSを発見するまでは音量取得元を確定しないためAndroidアプリを妨げない。AMSの値は変化がない時間で失効しない。初期値待ち5秒、GATT操作待ち35秒、エラー後5秒で再試行。AMS未提供時はService Changedと30秒周期の再探索で復帰を試みる。切断・Service Changedでは探索世代を無効化し、コールバックの結果と通知を破棄する。コールバック用メモリはNimBLEの完了通知まで保持する。

ホストテスト44件、fmt、ESP32-C3ビルド成功。1,370,784バイトを書き込み、ハッシュ一致。

2026-11-14のiPhone実機確認で暗号化接続、AMSサービス探索、Service Changed／Entity Updateの購読、Player Volume初期値38%の受信に成功。続く31%→25%→31%の更新と、LED出力011→001をUSBログで確認した。

当時の検証記録（現在は登録済み端末も新規受付中に接続可能）：登録済みiPhoneへの再接続にはノブ長押しは不要。旧仕様では新規ペアリング待ち中に登録済み端末を拒否していたため、長押し後の再接続でiPhoneにタイムアウトが表示された。60秒の点滅終了後に通常接続すると成功した。

仕様: [Apple Media Service](https://developer.apple.com/library/archive/documentation/CoreBluetooth/Reference/AppleMediaService_Reference/Specification/Specification.html)、[Player Volumeの書式](https://developer.apple.com/library/archive/documentation/CoreBluetooth/Reference/AppleMediaService_Reference/Appendix/Appendix.html)。

ノブ操作についてもユーザーがiPhone音量・3連LED双方の追従を確認。USBログでHID VolumeDown送信、AMSの50%→44%更新、シーケンス終了後のLED出力011への復帰を確認した。Service Changedでの再探索、iPhone切断・再接続後の音量再取得は未確認。

## Androidとブラウザの共通表示エディター（v3）

`firmware/src/editor.html`をブラウザで配信し、同じファイルをAndroidのビルド時にアセットへ取り込む。静止画は1コマ、アニメーションは最大8コマとして扱い、プリセット・ドット編集・周期・明るさ・待機モードを両方で編集できる。プレビューは編集画面内だけで再生する。

Androidは通常のBluetooth接続で0008を読み書きし、Wi-Fiへの切り替えは不要。MTU 128を要求し、78バイトの設定を転送する。保存後に全設定を読み戻して一致を確認する。ブラウザは従来のHTTP APIを使用する。通信形式が変わるためファームウェアとアプリを同時に更新する。

実機回帰用の`HeadphoneStandHardwareTest#sharedDisplayRoundTrip`は1コマ／8コマと各待機モードを保存・読み戻しし、最後に元の78バイトを復元する。
