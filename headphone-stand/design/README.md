# 操作部の絵と共通エディター

## CADから測定した正面比率

元データ: maker-projects/nothing-headphone-accessory/STEP/clumo_tower_main.step（現行採用組立）。cadスキルのread_sceneから部品のワールド座標外接寸法と正面の面を測定。単位mm、X右・Z上。記録は[control-panel-measurements.json](control-panel-measurements.json)。CAD自体の変更なし。

- 操作パネル: 73×73、X=-36.5..36.5、Z=8.5..81.5
- マトリクス表面: 43.2×43.2、中心(-14.9,59.9)
- ボタン中心: (-16.4,22.9)と(0.6,22.9)、間隔17。リングφ9、ボタン外接φ7.4
- ノブ: 中心(22.1,22.9)、φ18
- LED窓: 中心X=22.1、Z=69.45/60.45/51.45、アクセント窓Z=42.45。正面の面6×6、裏つば外形8×8
- 縦ライン: 1.8×18、中心(-27.95,22.9)

AndroidのHeadphoneStandDeviceはこの正面比率で操作部のみを描く。影・段差は省略し、外周の余白はイラスト用。3連LEDの絵は音量テレメトリではない。

## Webのデザイントークン

AndroidのClumoColors.ktを色の元データとする。余白は8/16/24、カード角丸28、操作ボタンはピル型・48px以上。Androidと同じM PLUS Rounded 1cの英語用サブセットをHTML内へ同梱するため、設定Wi-Fiにインターネット接続は不要。アプリ内では重複したWeb見出しを隠す。編集操作とデータ形式は共通。

再生成（Python fonttools 4.42.1使用）:

```sh
python3 headphone-stand/tools/sync_editor_style.py
```

HTMLはAndroidビルドでアセットへコピーし、ESP32では同じHTMLを埋め込む。変更時は両方をビルド・更新する。Webは標準配色を使い、端末別の外観設定によるアクセント変更は未連動。

検証: Android debugビルド・ktlint成功、ESP32 releaseビルド成功、1,412,096バイト書き込みハッシュ一致。Android実機で操作パネル比率・編集画面の書体と配色・保存済みデータ読み込みを目視確認。Wi-Fiブラウザでの今回の外観確認は未実施。

UI文言整理: 操作説明・音量連携・Wi-Fi／ペアリングは項目横のヘルプへ移動。エディターは重複見出しとプリセット説明を削除し、コマ数・最低輝度・保存反映条件だけ補足ヘルプ化。エラーと未保存／保存状態は常時表示。Androidビルド・ktlint、ESP32ビルド成功、両実機へ更新済み（1,412,736バイト）。

## スタンドの部位別配色

外装・操作パネル・マトリクス面・ボタン・LED窓・アクセント（ノブ／縦ライン／下の窓）の6部位と、画面上のLED色を設定する。外装、ボタン、アクセント、LED色は既存の保存値を引き継ぎ、追加したpanel・matrixSurface・windowは欠落／不正値時に個別の標準色へ戻す。初期化はその端末だけに適用。実物の発光色を変更する機能ではない。

主端末がスタンドの場合、アプリのテーマは標準配色で固定し、本体の配色から分離する。従来CLumoの4項目とテーマ連動は維持。Android単体テスト・ビルド成功、USB接続端末へ更新済み。
